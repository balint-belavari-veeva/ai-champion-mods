# Changelog
- One setup (2026-11-12): new `ai-champion` plugin 1.0.0 with `/ai-champion:setup` (auto-update for the marketplace, plus the status line if `statusline` is installed). `/cache-keeper:setup` removed (cache-keeper 2.12.1); `/statusline:setup` now only sets up the status line (statusline 1.0.1), auto-update moved to the new setup.
- Split (2026-11-12): cache-keeper 2.11.0 no longer contains the Vault picker; it is the new `vault-login` plugin 1.0.0 (own module, `/vault`, `vault-track.py` hook, one band row with the CLI's current Vault, `/vl-vault` fallback name). The status line script and setup moved to the new `statusline` plugin 1.0.0 (`/statusline:setup`); `/cache-keeper:setup` now only enables auto-update. goal-meter, recording-mode and collision-guard removed from this marketplace (the code stays in git history). Band layout: cache-keeper's right side is `agents`, `handoff`; the `vault` button moved to its own row.
- Packaging (no plugin version change): `veeva-vault-permissions` 1.0.0 added to this marketplace (moved out of the BI-specific bi-skills repo; no BI content in it). The status line script and `vault-track.py` now live in `plugins/cache-keeper/bin/` and the Vault tracking hook ships inside cache-keeper's `hooks.json` (standard PostToolUse entry next to the module), so `install.sh` no longer registers it in settings.json (remove an old `~/.claude/hooks/vault-track.py` entry or it runs twice). New `/cache-keeper:setup` skill (status line + `autoUpdate` for the marketplace). README rewritten for sharing.
- cache-keeper 2.10.0: terminal Vault picker no longer marks the CLI's current Vault (no ▸, no bold), so nothing is flagged on open except Vaults actually used in this chat; a click flags the one you picked and the earlier ones stay. Switching/log-in messages animate 0-3 trailing dots while busy (terminal and VS Code).
- cache-keeper 2.10.1: Vault picker login worked only while the session was valid: after it expired (e.g. overnight) "log in" failed with "The input device is not a TTY" because `vault login` prompts for a username and the mod has no terminal. Login now passes `--username` (read from `vault status`, else `vault user list`). Tested by hand: `vault login --dns X --username U -y </dev/null` opens the browser and succeeds.
- cache-keeper 2.9.3: fixed the agents pane never opening: `APANE` was used but never declared (ReferenceError in `openAgents` and the Pane render hook since 2.5.0). Verified with a `claude plugin test` run (band button opens the pane, cards draw, terminal and VS Code).
- cache-keeper 2.9.2: picker opens faster: `vault status` and `vault list` run in parallel (~2s each), and the auto-activate of the CLI's Vault no longer triggers a second full refresh (2.9.1 doubled the load time).
- cache-keeper 2.9.1: agents pane fix (`plain: false` / an empty Text made the tree invalid, so the pane never drew; draw errors now show in the pane). VS Code Vault picker flags the CLI's current Vault as active on open, unless deactivated earlier in the session.
- cache-keeper 2.9.0: band shows model + context bar in VS Code too (no status line script there: falls back to the session's own usage; terminal still reads the script's file). The band's `board` button is now `agents` (hotkey a) in terminal and VS Code; `/board` still exists. Vault search box now in the terminal picker too; its "log in again" button lost the `l` hotkey so typing in the search cannot trigger it.
- cache-keeper 2.8.0: VS Code Vault picker opens at once and shows "Checking Vault status…" while it reads the real state; only Vaults activated in this chat show as active (the CLI's current one just gets a dim "CLI here" tag); Activate/Deactivate buttons read "Activating…"/"Deactivating…" and lock the others while working. Terminal unchanged.
- cache-keeper 2.7.1: VS Code picker: removed "Point CLI here"; Activate now only marks the Vault active (CLI untouched, Claude switches itself). Max 6 active per chat.
- cache-keeper 2.7.0: VS Code Vault picker is multi-active. Buttons read Activate / Point CLI here / Deactivate (no more "Switch"); every active Vault stays highlighted. With 2+ active Vaults, a short note rides along with each typed prompt telling Claude the CLI points at one at a time and to `vault switch --dns` between them (never into production unless asked). Terminal picker unchanged.
- cache-keeper 2.6.0: VS Code Vault picker gets a search box (filters by name or DNS) and drops the "log in again" button while signed in (shown only when signed out). Terminal picker unchanged.
- cache-keeper 2.5.1: the agents pane command is `/ck-agents` (Claude Code has a built-in /agents that shadowed ours).
- goal-meter 1.1.1: Goal meter pane in VS Code is capped to 36 columns (was 50+ with a bar up to 120), which overflowed the narrow side panel and made the tab strip jump.
# Earlier history (pre-split)

- recording-mode 1.2.0: `/rec panel` opens a Recording pane (status, Start / Strict / Stop buttons, config counts) for VS Code and Desktop. `/rec` itself unchanged.
- cache-keeper 2.5.0: VS Code layout for the Vault picker (one card per Vault, native Switch / Confirm switch button on the right, active Vault marked); terminal picker untouched. New `/agents` pane (terminal text fallback too): each agent of this session with status, context bar, cost, request count, model, Refresh button; cost/context are tracked from the agent loop's own requests.

- install.sh: always runs `claude plugin marketplace update` before installing/updating plugins (previously skipped when `marketplace add` succeeded, which left stale plugin versions).

- cache-keeper 2.4.0: band leads with model + context bar, then the cache state (`Sonnet 5.5 [#-------] 5% ctx │ ● cache warm …`). Vault picker colours every Vault used in this chat (green sandbox, yellow production); the CLI's current one is also bold.
- cache-keeper 2.3.0: one place. The band now also shows model + context bar (`[##--------] 12% ctx`), read from `~/.claude/ctx-state/<session>.json`, which the status line script writes (it now prints nothing; only the status line gets the context % from Claude Code). Vault picker colours only the active Vault (green sandbox, yellow production); other rows plain. Run `install.sh` to refresh the status line script.
- cache-keeper 2.2.2: Vault picker rows no longer have 1-9 hotkeys (only the first nine had them); click only. `l` for log in stays.
- cache-keeper 2.2.1: status line no longer shows the Vault segment (picker only). Picker colours just the Vault's name (green sandbox, yellow production) while signed in; the tag and "used in this chat" stay dim.
- cache-keeper 2.2.0: Vault picker rows are coloured as a whole (green sandbox, yellow production) while signed in, plain when signed out; the tag now reads `⚠ production` instead of `⚠ not a sandbox`. New `board` band button (hotkey b) opens the Sessions board, same as `/board`.
- cache-keeper 2.1.0: Vault picker. A `vault` button on the band (reads `vault login` in red when the CLI session is gone; hotkey v) and `/vault` open a pane listing every Vault the login reaches (`vault list`), or the cached list when logged out. One click switches (`vault switch --dns`) or logs in (`vault login --dns`, opens the browser). Non-sandbox Vaults (amber ⚠) need a second press. Plain `log in` runs `vault login` so the CLI's own picker handles a first-ever login.
- cache-keeper 2.0.1: the band (handoff button, session cost) now always shows, including in resumed chats; cache shows "unknown until next message" until the first prompt.
- cache-keeper 2.0.0: handoff is one click. `runHandoff` sets `H.auto`; once the handoff is captured, the chat clears and continues by itself (waits up to ~10s for the handoff turn to end). `/handoff continue` and the `clear and continue` button still work. Earlier local edit kept: the `ctx <tokens>` segment is removed from the band (the status line shows context fill).
- recording-mode, goal-meter, collision-guard 1.1.0: unchanged code; version bumped and author line added.
- Status line (Vault segment removed in 2.2.1): Patrick's script plus a per-chat Vault segment (all Vaults this chat used, amber ⚠ for non-sandbox, CLI-switch warning). New `hooks/vault-track.py` (PostToolUse on Bash), installed by `install.sh`. Sandbox detection is a name/DNS heuristic in the script's `case`.
